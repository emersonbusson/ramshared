# SPEC - Windows virtual disk identity, counters, and performance matrix

## Closed Scope

In now:

- Fail-closed Windows property/counter/checksum audit.
- Explicit StorPort virtual-bus and non-rotating identity.
- VM Driver Verifier gate before physical deployment.
- Bounded multi-size, sector, queue-depth and workload matrix.
- Registered comparison/regression evidence.

Out now:

- Pretending to be NVMe, SATA, or physical SAS hardware.
- Automated Task Manager UI control.
- Product-volume pagefile or automatic-start promotion.
- Unbounded pressure or allocation through the GPU reserve.

## Current boundary — disabled staging only

This is a source/static and historical-evidence specification, not an
operational runbook. All lifecycle, storage, VM, guest, GPU, formatting,
pressure, and package terms below define guarded candidate contracts or retained
historical failure modes. They authorize no current action. Any future live
matrix requires the separately approved scope, exact private identity binding,
and before→action→after evidence; public text uses `SANITIZED_*` placeholders.

## Technical Decisions

| # | Decision | Why |
| --- | --- | --- |
| DT-1 | All orchestration is plan-only unless both `-Run` and `-ApprovePhysicalHost` are supplied. | Prevent accidental physical mutation. |
| DT-2 | Product lifecycle remains the only disk create/format/teardown authority and requires exact vendor/product/serial/size plus non-boot/non-system identity. | Avoid duplicating a destructive boundary. |
| DT-3 | Canonical activity evidence is locale-safe CIM plus direct unbuffered checksum I/O. Task Manager is secondary evidence. | UI values can be rounded, cached, or locale-dependent. |
| DT-4 | In `HwStorFindAdapter`, call `StorPortSetAdapterBusType(DeviceExtension, BusTypeVirtual)` and require `STOR_STATUS_SUCCESS`. The service INF `Parameters\BusType` fallback MUST also be `BusTypeVirtual` (`0x0000000E`), never SAS (`0x0000000A`), so registry fallback and runtime publication cannot disagree. Keep `AdapterInterfaceType=Internal`, SCSI direct-access INQUIRY and VPD B1 rotation rate `0x0001`. Do not claim NVMe/SATA/SAS hardware, TRIM or persistent media. | The first hardened VM run proved the previous INF fallback still advertised SAS even with the runtime API call. Microsoft defines `Internal` for virtual miniports and exposes a Virtual storage bus property. |
| DT-5 | Exact property acceptance is `MSFT_Disk.Size == config`, logical/physical sectors equal config, `MSFT_PhysicalDisk.MediaType == SSD`, `SpindleSpeed == 0`, `BusType == Virtual`, exact vendor/product/serial and mounted `MSFT_Volume.Size > 0`. Restart/refresh Task Manager before a secondary 1 GiB capture. | Separates API truth from UI scaling/cache. |
| DT-6 | `Measure-RamSharedDiskIo.ps1` uses PowerShell 5.1-safe integer seed generation, terminating measurement errors and a top-level non-zero failure exit. | The physical baseline showed a locale conversion error followed by exit 0. |
| DT-7 | Cells are: 64 MiB/4 KiB/QD1; 256 MiB/4 KiB/QD4; 1 GiB/4 KiB/QD4; 1 GiB/512 B/QD4; 2 GiB/4 KiB/QD16. Each runs sequential 1 MiB, random 4 KiB read/write, 70/30 mixed, flush and three-round integrity, with ≥3 repetitions. | Covers minimum, UI-visible capacity, sector compatibility, concurrency and bounded high allocation without a wasteful Cartesian product. |
| DT-8 | Physical order is consumer-first stop → zero residue → immutable install → require free VRAM ≥ size + reserve → start → exact format → workloads → supported stop. A Windows watchdog owns recovery; no service is force-killed and no foreign volume is remapped. | Preserves proven host safety. |
| DT-9 | Any integrity/error/timeout is red. Same-condition throughput regression >20% is red and 10–20% yellow. p99 latency >2× baseline, stop >30 s or any residue is red. With n=3, p99 is the maximum sample. | Makes regressions numeric without overstating small samples. |
| DT-10 | The accepted final state remains demand-start. | The package is test-signed and physical execution remains supervised. |
| DT-11 | Every distinct physical driver binary increments `DriverVer`. The bus/counter candidate moved from `10.0.26200.3` to `.4`; the queue-backpressure fix discovered during the physical matrix moves to `10.0.26200.5` dated 2026-08-01. Package hashes alone never satisfy BINARY_MATCH: after service start, the loaded `Win32_SystemDriver.PathName` hash and both service process image hashes MUST equal the installed immutable manifest. A mapped old image requires a supervised reboot and resume, never an in-place overwrite. | The physical post-reboot audit proved `.4` still mapped hash `D56C…9168`, while the backpressure candidate hash is `E492…7CCB`. Reusing `.4` would make DriverStore selection ambiguous. A new binary therefore requires a strictly newer rank, followed by loaded-image verification. |
| DT-12 | A unique exact RAW RamShared disk (vendor/product/serial/size, `PartitionStyle=RAW`, zero partitions) is a valid teardown identity. Gate A and Gate B still run, but volume lock/flush/dismount/unlock are N/A; teardown proceeds unregister → destroy → VRAM wipe → lease release. A mounted disk still requires the exact configured access path and the full lock/dismount sequence. | Physical evidence proved a volatile LUN is RAW after reboot and the old code then permanently refused stop because `Get-Partition` returned no object. |
| DT-13 | The SCM control handler reports `StopPending` with a 30-second wait hint, marks the STOP/SHUTDOWN atomic, and returns. A successful teardown must make `Stop-Service` return without an exception and report `Stopped`/Win32 exit 0. If a fail-closed Gate A/B or identity check refuses teardown, the service remains `StopPending`, preserves Online I/O, waits one second and retries the same transaction until the unsafe condition is removed; it never attempts `StopPending → Running`. | Microsoft requires a handler to report a status change while processing the control. VM evidence proved that publishing `StopPending` later from a monitor can return success yet SCM reverts to `Running`; physical and VM evidence also proved that explicitly reverting `StopPending → Running` leaves `ControlService` returning Win32 1061. |
| DT-14 | The physical matrix watchdog measures stale progress, not total campaign duration. The controller refreshes a heartbeat before and after every cell and workload; after 600 seconds without progress the independent Windows watchdog records a timeout and attempts bounded consumer-first service stop. Host shutdown is permitted only when the separately supplied `-AllowWatchdogShutdown` switch documents explicit approval for that run. | Five cells × three repetitions can legitimately exceed the former absolute 900-second timer. An unconditional shutdown could interrupt a healthy campaign and would violate the operator's requirement that any further reboot/shutdown receive prior permission. |
| DT-15 | Every prepared physical campaign requires an explicit alphanumeric `PackageRevision`, included in each cell's semantic prerelease version (`0.1.2-matrix-<cell>-<revision>`). Package preparation refuses an empty or malformed revision. Reusing a version plus `commit12` for different artifact hashes remains a hard refusal; the harness never deletes or mutates the prior immutable version to make a candidate fit. | Physical discovery found that a rebuilt uncommitted candidate inherited the base manifest commit and collided with a prior campaign's immutable directory. A campaign revision preserves DT-9 immutability and makes repeated supervised validation reproducible without claiming a false source commit. |
| DT-16 | Each workload snapshots the target volume's remaining bytes and caps the aggregate concurrent file footprint at 25% of that value, aligned to 4 KiB with at least 1 MiB per worker. Sequential iterations, random-position range, and integrity buffers use that per-worker budget (integrity remains capped at 8 MiB). The chosen budget is recorded in every sample. | The first physical 64 MiB cell proved that a fixed 32 MiB worker file can exceed the useful NTFS capacity after formatting/metadata. A proportional cap exercises the same workload classes across all cells without converting expected filesystem overhead into a false driver failure. |
| DT-17 | GPU reserve accepts `nvidia-smi --query-gpu=memory.free --format=csv,noheader,nounits` only when it returns exactly one strictly numeric sample. The numeric sample is authoritative even when Windows `sudo.exe` leaves PowerShell `$LASTEXITCODE = -1`; missing, multiple or malformed samples remain a refusal. | The physical elevated bridge returned a current numeric sample while exposing `-1`, causing a false “unavailable” refusal before allocation. Strict output validation preserves fail-closed parsing without trusting an interop-corrupted process status. |
| DT-18 | Exact mounted-volume observation has a 12-second child-process deadline inside a 15-second I/O-pumped host-call deadline. It remains bounded below the 30-second SCM wait hint and stop regression threshold. A timeout still refuses teardown and records code 7. | Immediately after format/direct-I/O churn, a correct Storage-provider query took more than the former 4-second budget and was killed with empty stderr; the identical settled query took 1.674 seconds. The former 4/5-second nested budgets created a false safety refusal and exposed the SCM refusal-recovery limitation. |
| DT-19 | The VM refusal drill MUST prove `STOP → manufactured pagefile refusal → SCM StopPending with process/I/O preserved → remove pagefile entry → the same STOP reaches Stopped → clean restart/STOP`, with no force-kill. A unit notifier handshake alone is insufficient closure. | SCM serializes control notifications and rejects another STOP while the first is pending. Retrying the safety gates inside the original transaction matches SCM semantics and preserves the fail-closed boundary. |
| DT-20 | After SCM reports `Running`, the physical harness polls exact `MSFT_PhysicalDisk` identity for at most 30 seconds at 250 ms intervals. Cardinality zero is the only retryable observation; cardinality greater than one or any size/bus/media/sector mismatch fails immediately. The successful enumeration duration is recorded per cell. | The 256 MiB physical transition proved SCM process readiness can precede Storage-provider enumeration. A single immediate query produced a false failure, while rollback enumerated normally. Bounded zero-only polling preserves strict identity and exposes actual PnP latency. |
| DT-21 | Matrix config rewriting accepts both LF and CRLF but only replaces an exact scalar assignment line. Before hashing/sealing a cell, package preparation reparses the effective broker and winsvc TOML and requires the planned size, sector, queue depth, and equal broker capacity. | Physical evidence proved the former end-of-line regex silently failed on CRLF: every named cell retained the 64 MiB config and valid hashes. Content assertions must precede the immutable manifest so a correctly signed package cannot misrepresent its matrix cell. |
| DT-22 | The QD16 concurrency cell uses `max_io_bytes = 262144`; the other cells retain 1 MiB. Package preparation requires `queue_depth × max_io_bytes ≤ 4 MiB` and asserts the exact effective value before sealing. | The live QD16 install correctly refused the inherited 1 MiB maximum because its 16 MiB aggregate exceeds the product's bounded in-flight limit. A 256 KiB maximum reaches QD16 while preserving the existing 4 MiB safety ceiling. |
| DT-23 | When `QSubmit` reports only temporary slot exhaustion (`STATUS_INSUFFICIENT_RESOURCES`), the miniport marks the exact LUN busy with one request to complete, completes the not-yet-started SRB as `SRB_STATUS_BUSY`/`SCSISTAT_BUSY`, and lets StorPort retry it. All permanent validation, mapping, disconnected, or failed-state errors remain `SRB_STATUS_ERROR`. | The physical QD1 flush drill produced an OS device-I/O error while backend evidence remained at zero errors. The old translation converted a full one-slot ring directly into permanent failure. StorPort's documented queue contract uses BUSY for temporary adapter/buffer pressure and reissues the original request. |
| DT-24 | Every physical cell writes a schema-versioned `context.json` before workloads start and completes it after teardown. It records the sanitized invocation, harness and repository revision/dirty state, campaign revision, UTC interval, Windows build, CPU/RAM/GPU/VRAM condition, planned cell, exact installed manifest/config/driver/service hashes, observed loaded hashes, before/after identity, commands, and a complete SHA-256 inventory of every non-context cell artifact. After the completed context is sealed, a separate per-cell `evidence-manifest.json` hashes that context and repeats the exact inventory, avoiding an impossible self-hash cycle. Missing, empty or contradictory required fields/artifacts are a failed campaign, never an implicit PASS. | The exploratory physical matrix verified live hashes but did not persist them, so its BINARY_MATCH and fixed-context claims cannot be independently audited. A two-level manifest makes the complete set independently verifiable without recursive self-hashing. |
| DT-25 | Campaign verdicts are ordered `RED > YELLOW > INCOMPARABLE > BASELINE > PASS`. `PASS` requires all rows, integrity/identity/teardown gates and a fingerprint-compatible qualified baseline. `BASELINE` is a valid complete measurement without a prior comparator; `INCOMPARABLE` is a valid measurement whose baseline fingerprint differs; both block regression claims and candidate promotion. `YELLOW` blocks promotion and requires repetition. `RED` aborts remaining work. Every non-PASS verdict restores the supplied LKG, preserves artifacts and exits non-zero; output MUST print the actual verdict, never unconditional `STATUS=PASS`. | The former harness could compute RED or YELLOW rows, then print PASS and return zero. It also treated an absent or incompatible baseline as if it were an accepted regression result. |
| DT-26 | A baseline is qualified only when its `schema_version`, harness behavior revision and platform fingerprint match. The fingerprint binds Windows build, GPU model/driver, RAM class, driver interface/config, sector, queue depth, max I/O, workload definition, warm-up and run count; it deliberately excludes candidate binary/hash and measurement timestamp. A mismatched or unqualified record is `INCOMPARABLE`, not a regression input. | Comparing only `cell,workload` can turn unrelated machines, drivers or workload definitions into false regression evidence. |
| DT-27 | The five-cell campaign requires exactly 75 unique sample rows (`5 cells × 5 workloads × 3 runs`), exactly 15 summary rows and complete per-cell counter/context/property/Event-153 artifacts plus the sealed per-cell evidence manifest. Duplicate or missing `(cell, workload, run)` keys, an empty required artifact, or any Disk-provider Event 153 inside the exact cell UTC interval are RED. Each summary records median throughput, sample standard deviation, minimum/maximum throughput and maximum observed p99 latency. | Aggregate averages and a nominal run count do not prove the required matrix actually executed, and the observability contract already requires deviation. |
| DT-28 | Storage-provider mutation and observation used by the matrix run in a dedicated child process with a 60-second deadline and a machine-readable result. On timeout the harness terminates only that orchestration child, records the exact phase and state, and enters supported product teardown. The independent watchdog submits the winsvc STOP without an unbounded wait, records SCM state, and stops the broker only after winsvc is `Stopped`; it never force-kills a service. A missing published volume after an exact partition appears is RED. | The 2 GiB/QD16 exploratory cell created the exact partition but hung in `Format-Volume`/`Get-Volume`. The stale-progress watchdog then blocked inside `Stop-Service` with winsvc `StopPending`, so it could not reach broker handling or rollback. |
| DT-29 | A watchdog timeout marker, incomplete cleanup, `StopPending` beyond 30 seconds, product residue, or failure to restore the selected final manifest overrides all performance results to RED. The final artifact records attempted and observed cleanup states even when cleanup fails. | Recovery evidence is part of correctness; a benchmark must not become green while the host remains in an indeterminate lifecycle state. |
| DT-30 | A recovery journal is a monotonic state machine: `raw_validated → partition_created → volume_published`. If and only if the bounded storage worker recorded the exact expected product LUN as RAW, then recorded `phase=partition_created`, and never recorded `phase=volume_published`, a separate 60-second recovery worker may revalidate exact friendly name, serial, size, disk number, non-boot/non-system flags, the single harness-created drive-letter partition, and **exactly zero** published volumes before `Clear-Disk` returns that volatile scratch LUN to RAW. Any absent/out-of-order/contradictory journal event, volume, or identity mismatch refuses recovery; no service is force-killed. The before/action/after record is retained even on failure. | The exploratory QD16 hang left a GPT `S:` partition with no `MSFT_Volume`. Finishing format was denied while the service retried fail-closed observation; clearing only the proven scratch LUN to RAW allowed the same pending STOP transaction to destroy it and release the lease. A `before_partition_style=RAW` flag alone did not prove that a published volume was not being destroyed. |
| DT-31 | Repository commit/dirty state, sanitized top-level arguments and host context are collected before the watchdog is armed. When elevated Windows has no `git.exe`, the WSL launcher supplies a 40-hex commit, `clean|dirty` state and consistent non-negative dirty-entry count; missing or contradictory values refuse before physical mutation. Loaded-driver evidence always hashes the exact `Win32_SystemDriver.PathName`, never a conventional `System32\drivers` copy. | Physical preflight proved elevated Windows has no Git and that the fixed system-driver copy can differ from the mapped DriverStore image. It also exposed that function-local `$PSBoundParameters` would otherwise persist an empty invocation and that a preflight exception after watchdog arming could leave recovery state behind. |
| DT-32 | The virtual adapter advertises `MaxNumberOfIO = MaxIOsPerLun = RAMSHARED_MAX_QD` but starts every new LUN at `InitialLunQueueDepth = 1`. Each disk tracks the first valid INQUIRY address and applied depth. After both INQUIRY and queue registration exist, `StorPortSetDeviceQueueDepth` MUST apply the exact registered depth (1/4/16 in this matrix). If registration observes a prior INQUIRY and application fails, it unregisters and refuses REGISTER; if the first INQUIRY occurs after registration and application fails at StartIo IRQL, it marks the disk failed and fails INQUIRY so owner-driven PASSIVE teardown can unregister safely. Temporary `QSubmit` full remains the residual `SRB_STATUS_BUSY` safety path, but an accepted QD1 mixed/flush drill requires zero Event ID 153 retries and zero I/O errors. This distinct binary uses `DriverVer = 08/09/2026,10.0.26200.6`. | Microsoft documents a default initial depth of 250 for virtual miniports and requires smaller per-LUN capability to be set explicitly. The physical `.5` run emitted dozens of Disk Event 153 retries and exhausted the default BUSY retry budget during QD1, proving that backpressure alone cannot substitute for advertising the queue's actual capacity. |
| DT-33 | Every PowerShell Direct session opened by the VM product-package harness uses the same bounded readiness policy: retry `New-PSSession` for at most 180 seconds at three-second intervals, then fail non-zero. A single connection attempt is not valid evidence, and a retry loop never masks package, driver, lifecycle, or test failures after a session is established. | The first `.6` product lifecycle run failed before deployment because `Run-GuestProductPackage.ps1` made one session attempt during the normal guest boot/remoting readiness window, while its caller already treated that window as transient. |
| DT-34 | CQ completion frees the exact internal ring slot under the queue spinlock after all bounce-buffer access is complete but before `StorPortNotification(RequestComplete, ...)`. `RequestComplete` may synchronously admit the next SRB, so retaining `RamSlotCompleting` across that callback creates a false full ring at QD1. Corrupt/reserved CQEs follow the same ordering. This distinct binary uses `DriverVer = 08/09/2026,10.0.26200.7`; the residual BUSY path remains only for genuine overload. | The `.6` QD1 VM drill emitted one Disk Event 153 at LBA `0x136a` despite the applied device depth. Source audit found the only normal completion path advertised the SRB complete while its sole slot was still unavailable to a re-entrant `HwStorStartIo`. |
| DT-35 | Any VM lifecycle exception after package installation triggers a bounded, supported consumer-first cleanup before the primary error is rethrown: submit winsvc STOP without force-kill, poll at most 60 seconds, stop broker only after winsvc is Stopped, record service/LUN/residue state in `failure-cleanup.json`, and preserve the original error. A manufactured post-Online failure must prove this path and terminal zero live residue. | The first `.6` zero-Event drill correctly failed on Event 153 but the harness exception bypassed its normal teardown, leaving both services and the LUN Online until manual supported cleanup. |
| DT-36 | If the VM format job times out after the exact LUN began RAW, the lifecycle harness terminates only that format job and runs a separate 60-second recovery job. Recovery revalidates one exact `RAMSHARE VRAMDISK` by disk number, serial, size, non-boot/non-system flags, requires exactly one harness-letter partition and zero published volumes, then clears only that volatile scratch LUN back to RAW. It records before/action/after in the failure artifact; any mismatch refuses recovery. Supported consumer-first cleanup then proceeds and the original format-timeout error remains primary. | The `.7` QD16 VM run timed out in format with one exact GPT `R:` partition and no volume. Generic failure cleanup correctly refused destructive teardown and left winsvc StopPending until a manual exact clear returned the LUN to RAW. |
| DT-37 | The adapter-wide `MaximumTransferLength` is 256 KiB, equal to the smallest registered `max_io_bytes` in the supported matrix. Larger application requests remain valid and are split by the Windows storage stack; no SRB reaching `QSubmit` may exceed the QD16 data slot. QD1, QD4 and QD16 mounted VM lifecycles each require zero Disk-provider Event 153 during their exact run interval. This distinct binary uses `DriverVer = 08/09/2026,10.0.26200.8`. | Both `.7` QD16 repetitions received format I/O up to the old advertised 1 MiB while the QD16 queue accepted 256 KiB. Requests were rejected before backend accounting, producing repeated Event 153 at the same LBA and a format timeout despite zero backend errors. |
| DT-38 | Startup LUN discovery uses a 12-second bounded Storage-provider child inside a 15-second I/O-pumped host-call deadline and retains the 60-second overall readiness bound. The inner operation MUST finish before the outer deadline so a slow provider does not create abandoned discovery workers. The lifecycle harness waits for an `Online` row from the current winsvc PID/run before any disk mutation; SCM `Running` plus an early `Get-Disk` object is not product readiness. A stopped service, non-unique run file, `FailedSafe`, or readiness timeout fails before format. | The `.8` QD4 VM run saw the exact disk while winsvc was still in `DiskCreated`; every five-second discovery child met an equal five-second outer deadline, the outer call timed out first, and startup eventually destroyed the disk. The harness then raced `Initialize-Disk` against that supported unwind. Nested timeout headroom and current-run Online evidence close both the runtime failure and the orchestration TOCTOU. |
| DT-39 | The physical matrix executes the counter/direct-I/O probe in a dedicated PowerShell child with a 45-second deadline, asynchronously drains both child output streams while it waits, and terminates the entire harness-child process tree on timeout; it never targets product services or unrelated processes. The probe uses only PowerShell 5.1-supported job cleanup; an invalid `Stop-Job -Force` call is forbidden. Timeout, nonzero exit, missing or semantically invalid JSONL, or zero activity is RED. | A synchronous `ReadToEnd()` after `WaitForExit()` can deadlock when a child fills either redirected pipe. Windows PowerShell 5.1 does not implement `Stop-Job -Force`; killing only the controller child can orphan its `Start-Job` process. |
| DT-40 | After the manufactured Gate A marker, the refusal harness polls the strongly typed `Get-Service.Status` for at most five seconds and requires `StopPending` before removing the synthetic pagefile entry. One CIM sample is not evidence of the transient SCM state. The observed terminal value is included in any failure, and pagefile restoration remains in `finally`; the existing 30-second bound for completion of the same STOP is unchanged. | The live `.8` refusal emitted the required Gate A and pending-transaction diagnostics, then completed the same STOP cleanly after restoration, but a single `Win32_Service.State` sample produced a false RED. | DT-41 | Before any `Initialize-Disk`, `New-Partition`, or `Format-Volume`, the storage worker receives the serial from one unique current winsvc PID/run `Online` evidence row and binds it to exactly one normalized `RAMSHARE VRAMDISK`: exact serial and planned size, logical and physical sector sizes, `BusType=Virtual`, `MediaType=SSD`, `SpindleSpeed=0`, non-boot, non-system, `PartitionStyle=RAW`, and zero partitions. Friendly-name prefixes, size-only selection, and stale or ambiguous evidence are refusals. | A current SCM `Running` state and a size-matching product-looking disk do not prove that the LUN belongs to the process that owns the present campaign. |
| DT-42 | Every matrix Storage-provider observation, including product-residue checks, target-letter preflight, candidate identity, final active identity, and recovery volume cardinality, executes in a dedicated bounded child process with a typed machine-readable result. A timeout, malformed result, or non-unique identity is RED. | The first bounded format worker did not protect controller-side preflight and final-state calls, so a hung provider could still wedge the watchdog owner. |
| DT-43 | Product-volume pagefile preflight rejects both active `Win32_PageFileUsage` entries and configured `HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management\PagingFiles` entries for the target letter. | DT-44 | Controller installation, GPU reserve sampling, workload execution, and all redirected child calls have explicit deadlines with process-tree termination. | DT-45 | The terminal state requires a fresh exact current-run `Online` evidence row and exact final Storage-provider identity, plus loaded driver/broker/winsvc BINARY_MATCH. If LKG install/start/verification fails, it attempts the same bounded stop again and records the terminal residue; no PASS, active claim, or implicit fallback is allowed. | A failed fallback can otherwise leave a candidate service running while the summary labels the selected manifest as rollback. |

| DT-47 | Every P0/P1 refusal is exercised by an executable manufactured case that invokes the real guard and observes a nonzero result or typed refusal artifact. ## Atomicity And Rollback

- Driver frontier: bus-property declaration only; no queue/uAPI layout change.
- Package frontier: one immutable manifest per configuration.
- Runtime frontier: supported consumer-first teardown before every switch.
- Rollback to the last physical-proven manifest if enumeration, identity,
  integrity, latency, stop or residue gates fail.
